# P-20W Gold-Layer Data Model Options
### ODS → Databricks (Delta Lake, Unity Catalog, medallion) — three candidate models

**Basis:** every in-scope row of `allDataElements.csv`: 2,593 rows across 94 inventory tables. Justice (42 rows), Special Populations and Programs (25) and IPEDS (36) are excluded. The models are checked against the published CEDS v14 artifacts in `github.com/CEDStandards`: CEDS-IDS DDL, CEDS-Data-Warehouse v14.1 DDL and the CEDS-Elements v14 workbook. Extracts are in `reference/ceds_v14/`.

**What is generated vs. written.** The column-level lineage, table catalogs, governance tags and DDL are generated by `scripts/build.py` from a single routing spec (`scripts/routes_*.py`). The build fails if any in-scope inventory row lacks a target in any model. This document explains the design choices behind that spec. Section 9 lists the files.

### 1.2 Legacy → current transitions, verified against First/Most Recent Year

Before treating any two elements as duplicates, I compared their Source/Program and year ranges. These pairs are **one conformed concept with a source changeover**, so each model stores them in one target column with source-period provenance:

| Concept | Legacy source (years) | Current source (years) | Evidence in inventory | Treatment |
|---|---|---|---|---|
| Student discipline | CEDARS *Discipline* (2012-13 → 2017-18) | CEDARS *Exclusionary Discipline* (2018-19 →) | Non-overlapping ranges; same keys; element renames (InterventionCode→ExclusionaryActionTypeCode, IsInIAES→SPEDInterimAlternativeEdSetting, OtherBehaviorIds→OtherBehaviorCodes …) | One table. `discipline_record_scope` flags that the legacy file included **all** corrective actions while the current file includes only exclusionary ones, so trends are not silently broken |
| First US school entry, months of US / non-US schooling | CEDARS *LEP* (2009-10 → 2010-11) | CEDARS *Enrollment* (2011-12 →) | LEP rows 1325–1327 note "Also in Enrollment in 2010 and 2011. Data in Enrollment only from 2012 on." | Conformed into the K-12 enrollment columns |

| Initial SPED referral / eligibility dates | CEDARS *SPED* segment file (2009-10 → 2017-18) | CEDARS *SPED Eval* (2020-21 →) | Rows 1460–1461 marked inactive Feb 2017; SPED Eval starts 2020-21 | Conformed into the initial-evaluation grain; **2018-19 and 2019-20 are a true gap**, not a duplicate |
| Race / ethnicity code sets | CEDARS legacy codes (last used 2021-22) | Expanded codes (from 2018-19) | Rows 1130, 1434 | Same attribute; `source_code_set` recorded; overlap years handled by effective dates |
| ECEAP enrollment & eligibility | *Hist ECEAP* (2000 → 2012) | *ELMS* (2013 →) | Non-overlapping ranges | Conformed enrollment and eligibility tables; the legacy race *indicator flags* are unpivoted into the same multi-valued race structure |

These look alike but are **genuinely distinct concepts**, and none of the models merges them:

| Pair | Why they stay separate |
|---|---|
| CEDARS *Grade History* vs *Student Schedule* | Both carry grades from 2019-20. Grade History is the **transcript** (final grading period, includes transfer courses, no section). Student Schedule is the **section roster**. They are different events, so both are kept with a `record_type` |
| *Non-Traditional Credit Attempt* vs *Grade History* | Credit without a course section |
| *Report Card School Enrollment* (2005–2023) vs CEDARS Enrollment (2009-10 →) | Published school-level aggregates vs student records. Report Card is the only pre-CEDARS K-12 series, kept as an organization-year snapshot |
| *OSPI School Directory* vs CEDARS *Location* | Organization master vs school calendar |
| *S-275* vs *Staff Schedule* vs *Retention/Mobility* | Payroll assignments vs teacher-of-record by section vs derived annual status |
| SAT scores before vs after 1 March 2016 | Inventory row 1982 says the scales are **not equivalent**; separate columns |
| SBCTC *StuClass* vs *Transcripts* | Same class-ITEM record split across a funding/credit-enrolled file and a grade/credit-earned file. **Reconciled to one record** (see 5.3), not treated as two concepts |
| PCHEES *admission* vs EPP *Admissions* | Admitted-and-enrolled records vs true applicants with decisions |

### 1.3 Findings that refine the "known context"

I followed the known context throughout. Four items are refined by evidence in the inventory or the CEDS repositories, and each affects the design:

1. **CEDS coverage is thin in the DW, not absent.** CEDS-Data-Warehouse v14.1 has native `FactQuarterlyEmployments` + `DimEmployers`, `FactCredentialAwards`, `FactPsStudentEnrollments`, `FactPsStudentAcademicRecords`, `FactPsStudentCourseTranscripts` and `FactPsStudentAcademicAwards`. CEDS-IDS v14 has `FinancialAidAward` (type/status/amount/year only), `PsStudentFinancialAid`, `PsStudentApplication`, `PsStudentAdmissionTest`, `ProgramParticipationTeacherPrep` and `TeacherEducationCredentialExam`. Neither has warehouse facts for financial aid, apprenticeship, EL enrollment/assessment, or PS applications. Model A therefore uses native CEDS for wages and credentials and original CEDS-aligned tables everywhere the known context expects.
2. **The public 4-year "applicant" grain in the inventory is an admitted-student grain.** PCHEES `admission` describes the term a student *first enrolled after being admitted* (row 1959) and has no denied or withdrawn applicants. The only true applicant grain with decisions is **EPP Admissions**. Admission stays a separate grain from enrollment, as instructed, but 4-year *applicant* analyses are not supported by the inventoried data.
3. **Financial aid is annual, not term-level.** The WSAC Unit Record grain is student × institution × **award year**. Term linkage is carried as five enrollment-status codes (Fall/Winter/Spring/Summer1/Summer2). An award therefore ties to 1–5 term enrollment rows, not to a single one (see 5.4).
4. **Not every enrollment source is periodic.** L&I apprenticeship is a registration **spell** (apprentice × program × occupation, status as of the data pull). NSC reports attendance periods with begin/end dates. Subsidy is **monthly**. ESIT has **no service dates at all** in the inventory. Model C's periodic enrollment rule is applied using each source's actual reporting period (5.2).

### 1.4 Inventory quality issues that affect implementation

- **Year labels mangled by Excel.** First Year Available values such as `2/1/1901` (eCert), `3/1/2002` (S-275), `5/1/2004` (SBCTC), `12/1/2011` (WaKIDS) and `7/16/1905` (SBCTC INSTRUCTION_MODE, Excel serial 2024) look like school-year labels coerced to dates. Year ranges were read with that in mind.
- **Unreliable `Primary Key?` flags.** For example, CEDARS Enrollment flags `DistrictName` and `HomelessDescription`. Grain and keys were derived from element semantics and the source dictionaries instead.
- **Partial SBCTC element lists.** The inventory lists subsets of each SBCTC table, alphabetically interleaved; the SBCTC PDFs in the folder hold more fields. Lineage is complete *for the inventory*. Uninventoried SBCTC fields would be added to the routing spec the same way.
- **One source table is itself EAV.** `ELMS.ApplicationDataBooleanQuestion` is "one observation per question, unflattened". To satisfy constraint 1 it is pivoted to one explicitly named BOOLEAN column per question. That requires the ELMS question lookup (question IDs 8–223), which is not in the inventory.

## 2. Foundations shared by all three models

The three models differ **only in gold**. Everything in this section is identical across them, apart from table naming. The practical consequence is that **bronze and silver can be built before the gold decision is final.**

### 2.1 Medallion responsibilities

| Layer | Content | Notes |
|---|---|---|
| **Bronze** (`p20w_bronze.<agency>`) | Each source extract as landed (Auto Loader / COPY INTO), append-only, with ingest metadata (file, batch, Delta version) | Keeps everything, including the 16 elements excluded from gold. ERDC-admin access only |
| **Silver: source-conformed** (`p20w_silver.<source>`) | Typed, cleansed, deduplicated per source grain. Code sets standardized. Legacy→current conformance applied (1.2). Period codes translated. SBCTC StuClass+Transcripts reconciled to ITEM records | Materially different from gold in every model: it stays source-shaped |
| **Silver: identity** (`p20w_silver_restricted.identity`) | Person matching (2.2) → `PERSON_XWALK`; PII observations | Restricted catalog; the only place PII is joinable |
| **Silver: org mastering** (`p20w_silver.org`) | `ORGANIZATION`, type satellites, `ORGANIZATION_XWALK`, `ORGANIZATION_LINEAGE`, closure (2.3) | Steward-maintained seeds + source masters |
| **Gold** (`p20w_gold_ceds` / `_custom` / `_conformed`) | Model A, B or C | Facts carry durable `person_id` / `org_id` / `academic_period_id` only |

### 2.2 Person identity (constraint 3)

**Durable key.** A single `person_id` (BIGINT) issued by the ERDC identity service and never reused. It is the research ID for elements marked *RI) Research ID will be Provided*. The inventory shows an MDM already exists: NSC `TokenID` is described as "the ODS TokenID, which is also the MDM ROWID_XREF … the person key" (row 2094). Existing tokens seed `person_id` so current ODS joins survive the migration.

**Source identifiers resolved** (all land in `PERSON_XWALK` with `source_system` and `identifier_type`):

| Identifier type | Sources (inventory elements) |
|---|---|
| `OSPI_SSID` | All CEDARS files, Assessments, WaKIDS (`WaK_SSID`, `WaK_StateStudentID`), Open Doors, ELMS `SSID`, TSGold `SSID`/`ELMS_SSID`, PCHEES `K12_state_ID`, College Bound `ApplicationSSID`/`LastReportedSSID` |
| `DISTRICT_STUDENT_ID` (scoped by district) | CEDARS `DistrictStudentID`/`DistrictStudentCode`, WaKIDS, Open Doors |
| `SBCTC_DW_KEY`, `CTCLINK_EMPLID`, `SBCTC_SID` | SBCTC Student, StuClass, Transcripts, Completions, Student Plans |
| `PCHEES_STUDENT_ID` (scoped by institution) | PCHEES `student_institution`/`student_OFM` |
| `EPP_STUDENT_ID`, `EPP_APPLICANT_ID` | EPP files |
| `INSTITUTION_STUDENT_ID`, `WSAC_SAMPLE_ID` | WSAC Unit Record |
| `ELMS_CHILD_ID`, `ELMS_FAMILY_MEMBER_ID`, `HIST_ECEAP_CHILD_KEY`, `ESIT_CHILD_ID`, `SSPS_SR_ID` (+ household `SSPS_CASE_NUMBER`), `TSGOLD_*`, `WAKIDS_CHILD_ID` | Early learning |
| `LNI_APPRENTICE_ID` | L&I. The inventory notes it is *not* one-to-one with a person (row 804) |
| `OSPI_CERTIFICATE_NUMBER`, `OSPI_EDUCATOR_ID`, `OSPI_PERSONNEL_ID`, `DISTRICT_STAFF_ID`, `SBCTC_INSTRUCTOR_ID` | eCert, S-275, Retention/Mobility, Staff Schedule, Grade History, EPP mentor, SBCTC Class |
| `ERDC_MDM_TOKEN_ID` | NSC |
| SSN / SSN-4 (identity zone only, used as a match key) | UI Wage (the **only** person key there), WSAC, PCHEES, L&I, GED, EPP, eCert, S-275, College Bound |

**Matching tiers**, applied in order. Every link records `match_method` and `match_score`:
1. **Deterministic on authoritative shared IDs**: SSID across OSPI/DCYF/WSAC/PCHEES; EMPLID/DW_KEY within SBCTC; certificate number across OSPI educator files and EPP.
2. **Deterministic on SSN + birth date**, for sources without a shared education ID: UI Wage, WSAC, PCHEES, L&I, GED.
3. **Probabilistic** on name, birth date, sex and ZIP, blocked by birth year (e.g. Splink on Databricks, or the existing MDM engine): ELMS, Hist ECEAP, ESIT, Subsidy, TSGold, EPP.
4. **Clerical review queue** for links in the grey zone.

**Where the logic lives.** In a versioned Lakeflow/DLT pipeline in the restricted identity schema. Rules are code in the repo; outputs are `PERSON_XWALK`, effective-dated so an unmerge closes the old link and reissues, and `PERSON_PII_OBSERVATION`, append-only. Gold facts receive only `person_id`, looked up as of the record's period. Known inventory quirks are handled in matching rules: ELMS `FamilyMember.Birthdate` is actually the child's DOB (row 89); WSAC birth date may be shared as year-month only (row 2490); L&I IDs can be shared or duplicated (row 804).

### 2.3 Organization mastering (constraint 8)

#### Components

| Table | Purpose | SCD / behaviour |
|---|---|---|
| `ORGANIZATION` | Durable `org_id`, type, name, operational status | Type 2. **A rename is an attribute change, never a lineage event** |
| `ORG_<TYPE>` satellites | Type-specific attributes **and hierarchy** | Type 2; the parent FK is effective-dated on the satellite |
| `ORGANIZATION_XWALK` | Each source code → `org_id`, effective-dated | Non-overlapping ranges per code, so a **reused code** resolves to different orgs in different periods |

Query pattern, identical in every model apart from names:

```sql
SELECT e.*,
       e.ps_institution_org_id                                      AS org_as_reported,
       COALESCE(c.related_org_id, e.ps_institution_org_id)          AS org_current_successor,
       COALESCE(c.allocation_share_product, 1.0)                    AS allocation_weight
FROM   fact.ENROLLMENT e
LEFT JOIN conformed.ORGANIZATION_LINEAGE_CLOSURE c
       ON  c.org_id = e.ps_institution_org_id
       AND c.relationship_direction = 'SUCCESSOR'
       AND c.is_terminal_successor;
```

**Automated assertions** (run on every load):
1. No overlapping effective ranges per (source_system, identifier_type, code).
2. Every fact org code resolves for its period; unresolved codes go to a steward queue, not to a default org.
3. For each SPLIT/MERGE, the predecessor's xwalk ends the period before the event and the successors' xwalk starts at the event.
4. Allocation shares per SPLIT predecessor sum to 1.
5. The closure is acyclic.
6. Reconciliation: District 11 headcount per quarter equals Fort Steilacoom + Puyallup for 2001-02 … 2019-20, and matches SBCTC published totals.
7. A rename produces ORGANIZATION versions and zero lineage events.

K-12 district consolidations are not documented in the inventory. The same tables handle them once a source of LEA history is identified (§8).

### 2.5 SCD treatment for every dimension (constraint 5)

Sources arrive annually (CEDARS year-end, PCHEES final files, WSAC, EPP), quarterly (SBCTC, UI) or monthly (Subsidy), and are **restated**. Type 2 ranges are therefore keyed to the **source period the attribute applies to**, not the load date. Restatements reprocess that period's versions.

| Dimension (A / B / C names) | Treatment | Rationale |
|---|---|---|
| `DimPeople`+`DimPeople_WaExt` / `core.person` / `conformed.PERSON` | **Type 2** (sex, birth year/month, race/ethnicity roll-up, country of birth) | Survivorship results change as sources arrive; demographic history is reportable |
| Person race/ethnicity and language bridges | **Type 2 by observation period** (source start/end dates) | Multi-valued and time-varying (CEDARS start/end dates, code-set change) |
| `PERSON_XWALK` / `PersonIdentifierXwalk` | **Effective-dated link** | Merges and unmerges must be replayable |
| `PERSON_PII_OBSERVATION` | **Append-only** | Evidence for matching; never overwritten |
| `ORGANIZATION` / `core.organization` / CEDS `Dim*` org dimensions | **Type 2** | Name, status, type |
| All `ORG_*` satellites, incl. hierarchy parent | **Type 2** (effective by school year / term) | Grade span, locale, addresses, parent change over time |
| `ORGANIZATION_XWALK` | **Effective-dated, non-overlapping** | Code reuse |
| `ORGANIZATION_LINEAGE` | **Append-only event log** | Events are facts, not versions |
| `ORGANIZATION_LINEAGE_CLOSURE` | **Type 1** (rebuilt) | Derived |
| `ACADEMIC_PERIOD`, `DIM_DATE`, `DimDates`, `DimSchoolYears` | **Type 0/1** | Static calendars |
| `ACADEMIC_SESSION` / `DimCalendarSessions` / `DimOrganizationCalendarSessions` | **Type 1** | The period is in the key; corrections overwrite |
| `ASSESSMENT_INSTRUMENT` / `DimAssessments`, `DimAssessmentSubtests`, `DimAssessmentPerformanceLevels` | **Type 2** | Cut scores and instrument versions change (e.g. SAT redesign, WELPA→ELPA→WIDA) |
| `PROGRAM` (+ satellites) / `DimPsPrograms`, `DimTeacherPrepPrograms`, `DimApprenticeshipPrograms` | **Type 2** | Credits required, award level, CIP change |
| `COURSE`, `COURSE_SECTION` (+ satellites) / `DimK12Courses`, `DimK12CourseSections`, `DimPsCourses`, `DimPsCourseSections`, `DimElClassSections` | **Periodic definition** (period in key) with Type 1 corrections | Sources re-report the catalog each year or term |
| CEDS junk dimensions (`DimK12EnrollmentStatuses`, `DimAttendances`, `DimDisciplineStatuses`, `DimIdeaStatuses`, …) | **Type 1 / static** combinations | CEDS option-set combinations |
| All purpose-built code references (`ref.*`, `ceds_ext.RefWa*`), CIP | **Type 1**, retired codes kept with end period | Descriptions get corrected |
| Model A `_WaExt` extensions | Fact extensions: none (1:1 with the fact). Dimension extensions: follow the parent's Type 2 version | — |

### 2.6 Governance classification (constraint 6)

- **Column rule.** Every target column carries the **most restrictive** Governance Requirement among the inventory rows it derives from. `RI` is carried as a separate `p20w_research_id` flag because it is a handling instruction, not a tier. `NA` columns and everything in the identity schema also get `p20w_restricted_identity = true`.
- **Tiers used, most restrictive first:** NA › ERDC Admin Only › RC › RE › R › A3 › A1 › A0 › E › CN › (RI flag) › None. **The relative order of R vs A3/A1 and of RE vs RC is my judgment, and needs your confirmation (§8).**
- **Unity Catalog.** `governance/model_X_uc_tags.sql` sets governed tags on every column (`p20w_governance_tier`, `p20w_research_id`, `p20w_restricted_identity`) and on every table (`p20w_governance_tier_max`, `p20w_table_type`). ABAC column masks and row filters can key directly on those tags. `governance/model_X_column_classification.csv` is the same mapping as a table, suitable for loading into `governance.COLUMN_CLASSIFICATION`.
- **Consequence for Model A.** CEDS `DimPeople` natively carries names and birth dates, so PII lives in gold and must be masked. Models B and C keep PII only in the identity schema.

### 2.7 How constraint 1 (no EAV) is met

- Every inventory element becomes an explicitly named, typed column in a purpose-built table. Code descriptions go to **one purpose-built reference table per code set** (e.g. `ref.cedars_incident_behavior`), never a generic lookup.
- **Repeating groups are normalized into rows with fixed typed columns**: EPP/PCHEES `race_1..5`, ELP domain score groups, EPP exam slots 1–3, UI supplemental predecessor slots. This is not EAV: each row has the same typed columns with the same meaning, and the discriminator is a governed code, not an attribute name.
- **The source EAV** (ELMS boolean questions) is pivoted to explicit columns.
- **Financial aid** keeps one explicit amount column per aid program (60+ columns) in all three models. CEDS-IDS `FinancialAidAward` would model these as one row per award type. Whether that counts as EAV under your constraint is flagged in §8.

## 3. Model A: CEDS-DW/IDS native, extended

**In concept: the standard owns the shape.**

CEDS-DW is the schema, and WA data is translated *into* it. State codes map to CEDS option sets, repeating groups become CEDS rows (each ELP domain becomes a `DimAssessmentSubtests` row), and anything CEDS has no home for hangs off the CEDS row in a parallel `_WaExt` table. The organizing principle is conformance to an external vocabulary **and** an external structure. The payoff is that WA's warehouse looks like every other CEDS warehouse, so CEDS tooling, federal reporting structures and an already-published definition of each term come with it. The price is a permanent translation layer — one WA code typically lands in two or three places — and a DDL diff to absorb with every CEDS release.

### 3.1 Approach

| Schema | Content | Count |
|---|---|---:|
| `ceds_rds` | **Unaltered CEDS-Data-Warehouse v14.1 RDS tables**, populated where WA data exists. Codes are mapped to CEDS option sets; keys and names follow the published DDL | 68 tables |
| `ceds_ext` | WA extensions: `<CEDSTable>_WaExt` 1:1 with the CEDS row (raw WA codes, WA-only elements), plus `RefWa*` purpose-built code tables | 127 tables (incl. 74 `RefWa*`) |
| `ceds_aligned` | Original tables for concepts with no CEDS DW table. CEDS DW naming and patterns (Fact/Dim/Bridge), columns named from CEDS elements (IDS where available) | 35 tables |
| `conformed`, `identity` | Org xwalk/lineage/closure, period xwalk, identity (CEDS has no equivalent) | 7 tables |

**Conformance check.** Each native mapping was validated against the CEDS DW DDL. 32 intended native columns do not exist on the CEDS table and were re-homed to `_WaExt`; all are listed in `lineage/validation_report.md`. **About 27% of inventory rows (711 of 2,593) populate at least one native CEDS column.** The rest live in extensions or CEDS-aligned tables.

### 3.3 Characteristics

- **Repeating groups become CEDS rows.** ELP domains, WaKIDS domains and objectives, and TSGold domains become `DimAssessmentSubtests` rows. Enrollment splits across `FactPsStudentEnrollments` (status) and `FactPsStudentAcademicRecords` (GPA, credits), because CEDS separates them.
- **Person keys.** CEDS facts reference `DimPeople` version keys (`K12StudentId`, `PsStudentId`). DW v14.1 added `*_CurrentId` companions (upgrade script `2025-08-27-DimPeopleCurrent-and-FK-upgrade.sql`). The durable `person_id` is carried alongside.
- **Enrollment grain reconciliation.** SBCTC StuClass → `FactPsStudentCourseSectionEnrollments` + `…Fundings`. SBCTC Transcripts and PCHEES registration → native `FactPsStudentCourseTranscripts`. The PCHEES combined funding source → one `…Fundings` row. A consequence of CEDS's own boundaries is that registration and grade live in different tables for SBCTC but the same table for PCHEES.

## 4. Model B: fully custom, CEDS-vocabulary-aligned

**In concept: the sources own the shape.**

Table boundaries mirror the grains the source systems actually produce, and CEDS appears as naming vocabulary rather than as structure. The organizing principle is fidelity to operational reality. It is the cheapest path to a first load and the most direct lineage, and single-sector work is fast because one row holds the whole event. What it does not do is integrate: `person` and `organization` are the only conformed objects, so cross-sector meaning is deferred to query time and every mart that needs "all credentials" or "all assessments" re-implements the same unions and unpivots. The wide unified tables are also sparse in source-shaped ways that users have to know about.

### 4.1 Approach

Table boundaries follow **this system's grains and reporting**, including for K-12. Sources with the **same grain within a sector are unified into one wide table** with `source_system`, rather than one table per source. Column names use CEDS element names where a CEDS element exists (about 190 columns carry a verified CEDS element ID); otherwise source-faithful snake_case. There are no junk dimensions: codes sit on the fact and descriptions in `ref.*`.

### 4.2 Characteristics

- **Fewest joins for single-sector work.** For example, `k12.student_school_enrollment` holds GPA, credits, statuses and dates in one row.
- **Wide tables with source-shaped sparsity.** `ps.student_term_enrollment` has 115 inventory columns, many populated for only SBCTC or only PCHEES. Delta's columnar storage makes this cheap to store, but users must know which columns apply to which source.
- **Cross-sector integration is deferred to query time.** Examples: an "all credentials" view unions `k12.student_high_school_completion`, `ps.credential_award`, `ps.ged_completion` and apprenticeship completion; an "all assessments" view unions six tables with four unpivots (§6). Each cross-sector mart re-implements that conformance.
- Lineage is the most direct: 342 of 2,195 columns are derived.

## 5. Model C: conformed fact family with sector satellites

**In concept: the questions own the shape.**

Families are defined by what happened to a person rather than by which agency recorded it — an assessment result is an assessment result whether it came from TSGold, Smarter Balanced or an admissions test. Each family has a narrow conformed spine, with source-specific detail pushed into 1:1 sector satellites. The organizing principle is conformance to internal semantics rather than to an external standard. The unions Model B defers to query time are materialized as the family table itself, and adding a source becomes additive: one new satellite. The cost moves upstream, into agreeing what `credential_type` and `standard_met_indicator` mean across agencies — an organizational cost rather than a technical one, and the 112 conformance points in `lineage/validation_report.md` are precisely that agenda.

### Q2 (single-sector): K-12 chronic absenteeism rate by school and year

The metric here is the share of enrolled students with full-day absences ≥ 10% of enrolled days. OSPI's exact part-day rule needs minutes, which are not in the inventory.

**Model C**

```sql
WITH abs AS (
  SELECT person_id, school_org_id, academic_period_id,
         COUNT(DISTINCT attendance_event_date) FILTER (WHERE full_day_absence_indicator) AS full_day_absences
  FROM p20w_gold_conformed.fact.ABSENCE GROUP BY ALL),
enr AS (
  SELECT e.person_id, e.school_org_id, e.academic_period_id, SUM(d.number_of_days_in_attendance) AS days_present
  FROM p20w_gold_conformed.fact.ENROLLMENT e
  JOIN p20w_gold_conformed.fact.ENROLLMENT_K12_CEDARS_DETAIL d ON d.parent_id = e.enrollment_id
  WHERE e.sector = 'K12' GROUP BY ALL)
SELECT o.organization_name AS school, p.school_year_end,
       AVG(CASE WHEN COALESCE(a.full_day_absences,0) >= 0.10 * (e.days_present + COALESCE(a.full_day_absences,0)) THEN 1 ELSE 0 END) AS chronic_absence_rate
FROM enr e
LEFT JOIN abs a USING (person_id, school_org_id, academic_period_id)
JOIN p20w_gold_conformed.conformed.ORGANIZATION    o ON o.org_id = e.school_org_id AND o.is_current
JOIN p20w_gold_conformed.conformed.ACADEMIC_PERIOD p ON p.academic_period_id = e.academic_period_id
GROUP BY ALL;
```

**Model B** is the same shape without the satellite join, because `k12.student_school_enrollment` already holds `number_of_days_in_attendance`, plus `core.organization` and `core.academic_period`.

**Model A**

```sql
WITH abs AS (
  SELECT f.Person_CurrentId AS student, f.K12SchoolId, f.SchoolYearId, COUNT(DISTINCT f.AttendanceEventDateId) AS full_day_absences
  FROM p20w_gold_ceds.ceds_rds.FactK12StudentDailyAttendances f
  JOIN p20w_gold_ceds.ceds_rds.DimAttendances da ON da.DimAttendanceId = f.AttendanceId
  WHERE f.AttendanceEventDurationDay = 1.0 AND da.AbsentAttendanceCategoryCode IS NOT NULL
  GROUP BY ALL),
enr AS (
  SELECT e.K12Student_CurrentId AS student, e.K12SchoolId, e.SchoolYearId, SUM(x.NumberOfDaysInAttendance) AS days_present
  FROM p20w_gold_ceds.ceds_rds.FactK12StudentEnrollments e
  JOIN p20w_gold_ceds.ceds_ext.FactK12StudentEnrollments_WaExt x ON x.FactK12StudentEnrollmentId = e.FactK12StudentEnrollmentId
  GROUP BY ALL)
SELECT s.NameOfInstitution, y.SchoolYear, AVG(CASE WHEN COALESCE(a.full_day_absences,0) >= 0.10*(e.days_present+COALESCE(a.full_day_absences,0)) THEN 1 ELSE 0 END)
FROM enr e LEFT JOIN abs a USING (student, K12SchoolId, SchoolYearId)
JOIN p20w_gold_ceds.ceds_rds.DimK12Schools  s ON s.DimK12SchoolId  = e.K12SchoolId
JOIN p20w_gold_ceds.ceds_rds.DimSchoolYears y ON y.DimSchoolYearId = e.SchoolYearId
GROUP BY ALL;
-- Alternative: precompute CEDS DimAttendances.ChronicStudentAbsenteeismIndicator into FactK12StudentAttendanceRates.
```

### Join cost

| | Q1 cross-sector (one person) | Q2 single-sector (K-12 aggregate) |
|---|---|---|
| **Model A** | 4 union branches · ~16 dimension joins · 1 unpivot · schema knowledge of CEDS subtest/performance-level dims | 5 joins (1 extension) |
| **Model B** | 6 union branches · 1 join · **4 unpivots** · knowledge of 6 table layouts | **3 joins** |
| **Model C** | **1 table · 2 joins** (+1 per optional sector satellite) | 4 joins (1 satellite) |

The pattern generalizes. Model C costs one extra satellite join on single-sector questions and saves unions and unpivots on cross-sector ones. Model B is the reverse. Model A pays CEDS's dimensional join cost on both, in exchange for CEDS-shaped outputs.

## 7. Comparison matrix

No model avoids the cost of making six sectors' data answer one question. They differ in when that bill arrives and who signs for it.

| Model | Integration cost is paid | By whom | Recurring trigger |
|---|---|---|---|
| **A** | Up front, against an external standard | ETL developers, continuously | Every CEDS release |
| **B** | Later, per report | Analysts, repeatedly | Every cross-sector mart |
| **C** | Up front, against internal agreement | Data stewards, once per concept | Every new cross-sector concept |

Models A and C are both integration-first and differ in whether the definitions come from CEDS or from Washington. Model B declines to integrate in the gold layer at all and treats that as a mart-layer concern.

|---|---|---|---|

## 8. Decisions that need your input

CEDS-IDS `FinancialAidAward` instead uses one row per award type with a typed amount. Do you consider that row-per-award-type form EAV? It matters most for Model A's CEDS alignment.

   - (a) Re-merged Pierce (Spring 2020) gets a **new** org_id linked through lineage, rather than reusing the pre-2001 org_id. Agree?
